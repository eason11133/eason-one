## Product movement

The current Company Runtime no longer collapses a governed multi-Employee Project into an arbitrary serial Task chain when the optional orchestration planner is unavailable or returns unusable output.

Current fallback behavior:

- approved Task order is **not** treated as dependency truth;
- provisional CEO/manager assignment is **not** treated as dependency truth;
- formally independent branches remain independent;
- explicit `accepted predecessor` / upstream synthesis language creates a real dependency;
- explicit Research-consumer language or an approved Research branch explicitly created to inform downstream work creates Research → downstream dependencies;
- explicit final review language creates verifier dependencies;
- Engineering work that explicitly consumes an approved product/design brief depends on that product/design work;
- ambiguous branches stay independent and remain protected by normal Work verification/recovery rather than being serialized by guesswork.

The current governed Company Kernel uses this deterministic conservative DAG on planner failure. The historical total-serial fallback remains only as compatibility code and is no longer the current governed fallback owner.

## Why this matters for first usable Project trial

A temporary topology-model/provider problem should degrade orchestration quality, not turn Eason One back into a single-agent queue. One blocked capability/staffing branch must not become an accidental predecessor of unrelated employees merely because it appeared earlier in the approved Task list.
