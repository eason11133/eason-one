# Eason One V0.12.2 — Founder State Truth

V0.12.2 repairs the real Founder-delegation failures reproduced by Agent Run #80 and the stale Autonomous Meeting Validation Mission.

## Governed CEO delegation

- Execution routes use a strict `OPERATION_PLAN` schema; `ADVISORY + operation:null` is invalid.
- Transport success is not semantic success. An unusable CEO contract is stored as `FAILED / STRUCTURED_OUTPUT_INVALID`.
- Founder-declared TWD ceilings remain deterministic hard authority boundaries.
- Every new Operation proposal creates a persisted Founder approval event with Approve, Modify, and Reject choices.

## Truthful Headquarters state

- System-validation Missions cannot become the Founder’s current real Mission or global runtime banner.
- A Task or Employee is displayed as working only while a live worker lease/thread or active execution Run exists.
- `NEEDS FOUNDER` requires a persisted actionable governance event and a visible reason.
- Legacy Missions receive a deterministic completion reserve when their stored plan supports one; authority is never increased.
- Mission UI derives its primary state from one authoritative projection instead of presenting stale `WORKING`, `IDLE`, and `READY` labels as simultaneous truth.

## Artifact truth

- A successful Agent Run is not automatically a validated Founder result.
- The Task must be authoritatively complete and contain a real result, or be explicitly marked as a partial result.
- Task objectives no longer fall back as fake Artifact summaries.

## Interface preservation

- People and Meetings remain primary navigation.
- CEO Line is vertically and horizontally aligned with the clock and Founder avatar.
- The Mission gate exposes deterministic Approve, Modify, and Reject controls.

## Verification

`scripts/verify-v0122.ps1` compiles the project, checks SQLite integrity and foreign keys, and runs focused V0.12.0–V0.12.2 regression tests in an isolated writable pytest directory.
