# Eason One V0.11.0.4 — CEO Dialogue Persistence Hotfix

## Problem

The CEO Direct Line committed the Founder message before provider execution, but persisted the CEO reply only when a Run succeeded. A provider/configuration failure could therefore appear in the browser and disappear after refresh or server restart. The browser also appended a second client-only failure wrapper after already rendering the server's canonical failure reply.

## Fix

- Persist CEO replies for successful and failed Agent Runs.
- Persist the canonical CEO error reply when execution raises before a Run can complete.
- Apply the same persistence rule to the legacy Headquarters POST path.
- Prevent the browser from appending a duplicate transient error after rendering the server answer.
- Keep existing Founder/CEO history in `WorkMessage`; no schema or data migration is required.

## Verification

The patch adds regression coverage for provider exceptions, failed Agent Runs, refresh persistence, Run linkage, and duplicate client rendering. No Provider or Codex call is made during installation.
