# Eason One V0.11.0 — Stabilization Reset

V0.11.0 stops adding new Company OS features and stabilizes the one Founder path that must remain usable:

Founder → CEO → real Mission → Engineer → WSL2 Codex → live progress → reviewable result.

## Product changes

- Real company work and system-validation history are separated. Validation records no longer become HQ Current Mission, active work, employee workload, or company progress.
- HQ chooses the current real Mission from authoritative running work first, then the last real Mission opened by Founder, then real Founder decisions.
- A global runtime strip remains visible across HQ, People, System, and Mission pages while a Run is active and returns Founder directly to the active Mission.
- Mission Room is reduced to a Founder-first summary, five execution stages, latest activity, accountable Tasks, and Results. Full events, Runs, prompts, and diagnostics are collapsed by default.
- Mission snapshots cap history queries and remove the per-Task Run query pattern.
- Live elapsed and heartbeat labels update even when no other runtime field changes.

## Codex boundary changes

- Read-only Jobs use a writable Codex session/output surface, because the CLI cannot initialize when its entire filesystem is frozen.
- Eason One snapshots the governed repository surface before the Job, compares the exact after-state, and restores only Job-caused deltas.
- Pre-existing dirty files are not treated as changes caused by the current Run.
- Read-only Jobs are bounded to 12 commands, 12 relevant files, targeted line ranges, and 120 seconds.
- The unsupported `--ask-for-approval never` argument is removed from the real CLI command.
- Useful partial validation evidence remains visible as a Partial Result instead of being discarded.

## Data migration

- Known runtime, smoke, read-only validation, and archived validation Missions are tagged `SYSTEM_VALIDATION`.
- All other current Founder/project Missions are tagged `REAL_WORK`.
- The known validation-infrastructure boundary misclassification is resolved only when the Run's own evidence proves no Job-caused repository change.
- Stale WORKING/REVIEW Task presence is cleared for non-running Missions without fabricating completion.

## Verification

The installer performs no Provider call and no Codex task. It backs up managed files and SQLite, compiles changed Python, syntax-checks JavaScript when Node is available, runs the focused Founder/runtime regression suite with a private pytest temporary directory, migrates the real database, and renders real HQ/Mission pages before accepting the update.
