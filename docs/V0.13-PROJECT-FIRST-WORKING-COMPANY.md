# Eason One V0.13 — Project-first Working Company

V0.13 changes the Founder mental model from runtime machinery to durable Projects.

## Product contract

- Project is the Founder-facing unit of work.
- CEO is the primary work entry and selects the smallest sufficient organization.
- People and Meetings keep their existing successful UX and identities.
- Missions remain durable internal execution records under Projects and move to Advanced Mission Control.
- Results are concrete persisted outcomes, not successful Run labels.
- `NEEDS FOUNDER` is reserved for a persisted consequential decision with an actionable reason.
- `WORKING` requires real live execution evidence.

## New Project approval

For a new Project the CEO returns a durable Project identity plus the first bounded internal Mission. The Founder-approved budget is Project authority. The first Mission receives only its priced execution envelope plus bounded contingency, leaving authority for later Project work. Project success criteria are persisted as Founder-approved Company Brain decisions.

## Context and cost

HQ uses a lightweight Project read model. It does not load full Mission timelines, Meeting transcripts, raw Run history, or the whole Company Brain on first paint. Project Detail retrieves scoped work only when opened. Specialist work continues to receive bounded relevant context through existing CEO context composition.

## Delegation truth

Explicit delegated work cannot succeed as `ADVISORY + operation:null`. Semantic validation marks such a provider response failed. Completed Tasks without verification appear as unverified Task Results; file/test-backed structured outputs may be promoted to validated Artifacts.

## Acceptance

A Founder must be able to start from HQ, approve a Project contract, watch People/Meetings/Results from the Project, and use Mission Control only for advanced audit or recovery. All real provider smoke tests happen only after deterministic and mock regression verification succeeds.
