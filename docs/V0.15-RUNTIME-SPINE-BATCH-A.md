# Eason One v0.15 — Runtime Spine Batch A

Date: 2026-08-09

## Purpose

This batch implements the first additive vNext company-domain spine without redesigning Founder UI or replacing proven execution machinery.

The invariant is:

`Project -> WorkItem -> Employee allocation -> AgentRun -> Artifact -> verification/acceptance -> CompanyEvent`

Decision and Opportunity are first-class objects so later Governance, Founder Attention, Contribution and Research Observer layers can build on auditable truth instead of prose.

## Protected / unchanged

- Eason One visual language, color tokens and current v0.14 Founder UI
- Meeting Room UI and Meeting execution kernel
- Finance/Cost surfaces and CostEvent ledger
- Operation runtime
- AgentRun execution evidence
- Engineer -> local Codex connector and host validation
- Existing Project / Task rows and data

No destructive table rename or drop is performed.

## New / restored domain objects

- `CompanyEvent` — append-only cross-company truth stream
- `WorkItem` — additive mirror of legacy `Task`
- `OpportunityEvent` — allocator / eligible-pool / selected-Employee provenance
- `Artifact` + `ArtifactContributor` — first-class versioned work product
- `Decision` + `DecisionAlternative` + `DecisionEvidence` — first-class organizational decision

## Runtime integration

- New Projects emit `PROJECT_CREATED` / `PROJECT_ACTIVATED`.
- Production Task creation mirrors immediately into WorkItem.
- Assigned WorkItems emit `WORK_ASSIGNED` and record Opportunity.
- Task state transitions emit company-level work events.
- Successful Task execution materializes a first-class Artifact.
- AgentRun structured success alone remains `UNVERIFIED`.
- Engineering Artifact becomes `VERIFIED` only when persisted host-validation evidence says it passed.
- Artifact acceptance is separate from execution success and verification.
- CostEvent creation emits `COST_RECORDED`.
- OperationEvent and MeetingEvent are mirrored into CompanyEvent atomically.
- Existing Projects, Tasks, successful Runs, Operation events and Meeting events are backfilled idempotently at app boot.

## v0.14.1 compatibility

A previously rejected v0.14.1 build may have left additive `work_item`, `company_event`, or `opportunity_event` tables in the local SQLite database even after code rollback. This batch intentionally preserves those tables and upgrades missing columns in place. It does not drop their data.

## Not implemented in this batch

- ActionProposal / Governance execution boundary
- Structured Founder Attention / Founder Decision
- CEO wake loop and Context Capsule
- Contribution provenance rewrite
- Meeting outcome -> Decision / WorkItem materialization
- Memory lifecycle / Skill Asset / Resource economy

Those belong to subsequent batches and should consume this spine rather than invent another truth layer.
